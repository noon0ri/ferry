# 알려진 문제

구현 중 발견했으나 고치지 않기로 한 것들. 각 항목은 왜 남겨뒀는지와 언제 다시 봐야 하는지를 적는다.

## 성능

- **`SessionScanner`의 전체 재읽기 폴백** — 꼬리 256KB에 `ai-title`이 없으면 파일 전체를 다시 읽는다.
  실측상 실제 로그 23개 중 1개(1MB)에서만 발동해 비용이 아니다. `ai-title` 없는 대용량 세션이
  많아지면 `scan()`의 폴백 조건을 손봐야 한다. 성능 테스트가 감시한다.
- **콜드 스캔 예산이 코퍼스 크기에 정규화됨** — `실제_로그_콜드스캔이_회귀_가드_안에_든다`는 세션당
  시간을 재므로, 코드가 아니라 코퍼스가 변해도 결과가 움직인다. 고정 픽스처 벤치마크가 더 정확하다.
- **`updateMissingPaths()`가 3초마다 메인 액터에서 `stat`** — 대상은 프로젝트 수(현재 ~14개)라
  무시 가능. 프로젝트가 수백 개가 되면 detached 스캔 안으로 옮긴다.

## 정확성 (모두 저비용·저확률)

- **같은 tick의 mtime 충돌** — 파일이 mtime 갱신 없이 바뀌면 캐시가 낡은 세션을 내놓는다.
  mtime 캐시의 본질적 한계다.
- **`lastRecord`의 decoy 부분문자열** — `"cwd"`나 `"ai-title"` 문자열을 본문에 포함한 레코드에
  걸리면 파싱에 실패해 불필요한 전체 재읽기를 한다. 결과가 틀리지는 않고 비용만 든다.
  (아이러니하게도 Ferry 자신의 개발 로그가 이 문자열을 인용한다.)
- **`RelativeDateTimeFormatter`의 로케일 고착** — static으로 올려서, 세션 도중 시스템 로케일을
  바꾸면 반영되지 않는다.

## 표시

- **제목 폴백이 슬래시 명령 원문을 그대로 보여준다** — `ai-title`도 `custom-title`도 없는
  세션은 첫 사용자 프롬프트로 폴백하는데, 그것이 `<command-message>...</command-message>`
  같은 슬래시 명령 원문이면 그대로 노출된다. 실제 코퍼스에 한 건 있다.
  폴백 단계에서 그런 마크업을 걸러내거나, 사용자가 이름을 붙이면 해결된다.

## 설계상 남겨둔 것

- **`SessionStore.refresh()`와 `refreshAsync()`의 스레딩 계약이 다름** — 전자는 non-isolated 동기,
  후자는 `@MainActor`. 둘 다 public이고 문서에 차이가 명시돼 있지 않다.
- **`TerminalLauncher`가 모든 실패를 `.copiedToClipboard`로 합침** — 원인(권한 거부/AppleScript 오류)이
  구분되지 않고 `Failure.message`는 버려진다. 앱 어디에도 로깅이 없어 디버깅 시 가장 약한 지점이다.
- **겹침 테스트의 판별력 한계** — `겹친_refreshAsync가_교착하거나_결과를_잃지_않는다`는 두 호출이
  같은 픽스처를 스캔하므로 "새 결과가 낡은 결과를 이긴다"를 증명하지 못한다. 취소 가드가 잘못 놓여
  양쪽이 다 빠져나가는 경우는 잡는다. 제대로 증명하려면 호출별로 다른 결과를 내는 `scan` 주입이 필요하다.
- **Terminal이 새 창으로 열림** — `do script`에 `in window` 대상이 없어 매번 새 창이 열린다.
  탭으로 바꾸려면 AppleScript에서 최전면 창을 지정해야 하고, 창이 하나도 없는 경우를 다뤄야 한다.
